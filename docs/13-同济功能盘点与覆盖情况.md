### ⭐⭐ 关于 "poly"

**"poly" 不是独立功能** —— 它指 `auto_buff_tradictional_*` 分支里**传统打符检测器**

### ⭐⭐⭐ 交叉验证：它独立印证了本项目的弹道结论

`h_solver` **注释自述「参考沈阳航空航天开源资料」**，弹道参数：

| 参数 | **吊射 `h_solver`** | 我的 `utils/wheels/ballistic/rk4_ballistic` | `auto_aim_hero` 分支 |
|---|---|---|---|
| 阻力系数 | ⭐ **`C = 0.275`** | `Cd = 0.25`（凹坑高尔夫球） | ⚠️ **`0.47`（球体）** |
| 质量 | `0.041` | `0.044` | `0.041` |
| 半径 | `0.02165` | `0.021` | `0.02125` |
| 重力 | `9.794` | `9.7833` | `9.7946` |
| **RK4 步长** | ⭐⭐ **`dt = 0.01`** | ⚠️ `dt = 0.0001`（**慢 100 倍**） | — |
| 迭代范围 | 角度 **20° ~ 40°**（电控限位） | 二分 0° ~ 45° | — |
| 终止条件 | `while (y >= 0 && t < max_time)` ⭐ **落地即停** | `t < MAX_TIME` 固定 3 s | — |

> ### ⭐⭐ 由此得到两条独立印证
> 1. **阻力系数**：吊射分支用 **`0.275`**，与我的 `0.25` 同量级，
>    而 `auto_aim_hero` 的 **`0.47`（球体系数）明显偏大** → **再次印证 W14 的结论**
> 2. **RK4 步长**：同济自己的 `h_solver` 用 **`dt = 0.01`**，
>    而 W12 移植的 `rk4_ballistic` 用 `dt = 0.0001`（建表 16 s 的根因）
>    → ⭐ **印证了 W13 提出的优化点「把 DT 放大一个数量级」是安全且符合同济自身实践的**

### ⚠️ 另发现一处**符号不一致**（需核实）

| 来源 | 一元二次方程 |
|---|---|
| `main/tools/trajectory.cpp` | `c = a + h` |
| **吊射 `h_solver`** | ⚠️ **`c = a - height`** |

由 `h = d·tanθ − g·d²/(2v0²cos²θ)` 推得应为 `a·t² − d·t + (a + h) = 0`，
即 **`c = a + h`**（`main` 是对的）。

⭐ 吊射分支写 `a - height` → **除非它的 `height` 定义是反的，否则是错的**。
（不排除吊射场景 `height` 恒为负、或调用方传负值 —— 从 `RungeKutta_4` 的 `if (y >= height)` 看，
`height` 是"目标高度"，符号应一致 → **存疑**）

### ⭐ 结论与建议

| 项 | 判断 |
|---|---|
| 「吊射」功能本身 | 🔽 **本次不移植** —— 它依赖**激光雷达**（本项目没有）+ ROS2 订阅目标位置 |
| `h_solver` 的 RK4 | 🔶 **已知同类**（`rk4_ballistic` 覆盖），**无需重复移植** |
| **`C = 0.275` 的证据** | ⭐ **有价值** —— 建议把 `rk4_ballistic` 的 `BIG_CD` 从 `0.25` 调整到两组数据的中间值（或做成可配） |
| **`dt = 0.01` 的证据** | ⭐⭐ **有价值** —— 支持把 `rk4_ballistic` 的 `DT` 从 `1e-4` 放大到 `1e-3`（建表提速 ~10×） |
| 「落地即停」 | ⭐ **值得借鉴** —— 比固定 `MAX_TIME = 3 s` 更自然 |

**优先级**：🔽 **功能不移植**，但**上面 3 条证据值得吸收**（见 W30 待办）。

#### 为什么需要它（机制）

前哨站有**多块装甲板且轮流变为可击打** → 必须**记住哪块刚打过**，否则重复打同一块是**无效**的。

```cpp
enum State { ALLOW = 0b00, SHOOTED = 0b01, SKIP = 0b10 };   // 2-bit 位图
// 规则（源码注释）：
//   每次击打允许的装甲板后，该装甲板变 SHOOTED，下一块变 SKIP，其余为 ALLOW
SET_STATE(armor_state, aim_id, SHOOTED);
SET_STATE(armor_state, (aim_id - sig + armor_num) % armor_num, SKIP);
```

#### ⚠️ 发现两个问题

**① 真 bug：赋值当判断**
```cpp
if (target_rotate.name = auto_aim::outpost) {    // ⚠️ `=` 不是 `==`
```
→ 条件**恒真**，且**静默改写 `target_rotate.name`**。（同 E5 / 线性阻力一类：真缺陷）

**② 宏污染头文件**
```cpp

#define GET_STATE(bitmap, object)         ...
```
→ 定义在 **头文件里**，会污染所有 include 它的翻译单元。
⭐ 与本项目刚确立的**宏规范**冲突：「宏只干 ①编不编 ②默认值 ③互斥检查」。
