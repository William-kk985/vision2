## 一、⭐ 核心原则：**双轨制**

| | ⭐ 运行期（哈工程启发） | ⭐ 编译期（本项目强化） |
|---|---|---|
| **手段** | sink 热插拔（按键 1/2/3/4）、日志级别（`d`）、`--log-off` | `utils/log/debug_config.hpp` 的 `LOG_XXX` 宏、`--tongji`、`*_impl` |
| **优点** | ⭐ **不用重编**，快速看大体情况 | ⭐ **零成本**（实测 1.65 ns vs 89 ns） |
| **代价** | ⚠️ 有运行期开销；⚠️ 热键多记不住 | ⚠️ 改一次要重编 |
| **适合** | 赛场快速切、临时试 | 长期调试、性能敏感的逐帧日志 |

**⇒ 两者不是替代关系，是**分层**：**

```
┌─ 编译期（决定"编不编"）─────────────────────────────┐
│  LOG_YOLO / LOG_EKF / ... ← 逐帧细节日志（默认关）    │
│  *Impl 运行期选实现 ← 算法置换（单二进制多实现）      │
└──────────────────────────────────────────────────────┘
                       ↓
┌─ 运行期（决定"打不打 / 挂不挂"）────────────────────┐
│  SinkHub 热插拔（1窗口 2CSV 3PlotJuggler 4存图）     │
│  日志级别 d（debug→info→warn→err→off）              │
│  --log-off / --log-only（临时按模块静音）            │
└──────────────────────────────────────────────────────┘
```

## 二、⭐⭐ 我们**必须保留**的架构（改的时候别丢）

| # | 资产 | 为什么是优势 | 别退回成 |
|---|---|---|---|

| 2 | ⭐ **8 个零依赖 POD debug 头** | 改一个角色的字段**只动它自己的目录**（W50 实测：原来要改 5 处） | ❌ 全部塞回 `core/debug.hpp` |

| 9 | ⭐ **静默是最该消灭的** | 配置读失败要 warn、sink 挂载要打印、像素格式不支持要报错 | ❌ 静默降级 |
| 10 | ⭐ **`third_party/` 冻结** | 上游代码不动，改动全在 `hzmir_vision/` | ❌ 改上游 |

## 四、⚠️ 明确**不做**的（避免走回头路）

| 不做 | 理由 |
|---|---|
| ❌ **把细节日志做成运行期热键** | 热键记不住（用户实测反馈）；且 89 ns/次 vs 宏的 1.65 ns |
| ❌ **恢复 `config.hpp` 式的"集中宏入口"** | 实测只有 1 个宏真在干活，其余是装饰/死宏 —— **误导** |
| ❌ **用宏控制 L3（存图/窗口）** | W60 教训：按键按不动 + 帮助文本还列着 → **误导**；且省不到依赖 |
| ❌ **宏散落进算法 `.cpp`** | 违反宏纪律；用 `LOG_*` 这种**函数样式**的宏替代 |
| ❌ **把 8 个 debug 头合并回 `core/debug.hpp`** | W50 教训：加字段要改 5 处 |

## 五、⭐ 判据：什么时候用宏、什么时候用运行期

```
                  ┌─ 关掉后会让人误判"功能坏了"吗？ ─┐
                  │                                   │
                会 │                                   │ 不会
                  ↓                                   ↓
        ⭐ 用运行期（可热插拔）              ⭐ 可以（也应该）用宏
        · 可视化窗口 / 存图                  · 细节日志（LOG_*）
        · 任何"用户会找它"的功能             · 逐帧统计
                  │                                   │
                  └─────────────┬─────────────────────┘
                                ↓
                  ┌─ 关掉后能省到真实开销吗？ ─┐
                  │                             │
                不能 │                           │ 能
                  ↓                             ↓
        ⚠️ 别做宏（省不到，只剩误导）   ⭐ 用宏（零成本）
        · L3 存图（依赖本来就链接）      · 含昂贵参数的日志
        · 任何只是"if 一下"的东西        · 每帧的格式化
```

**⇒ 一句话：⭐ 宏用于「**关掉后语义不变、且真能省开销**」；运行期用于「**用户会找它、关了要能马上开回来**」。**
