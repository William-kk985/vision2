# 四兵种通信方式

> 本文记录四个兵种与下位机/导航之间的通信链路、协议与配置。
> ⭐ 结论：**与同济上游完全一致**（步兵/英雄走串口，哨兵/无人机走 CAN，仅哨兵接 ROS2）。

---

## 1. 总览

| 兵种 | 下行（视觉 → 下位机） | 上行（下位机 → 视觉） | ROS2 桥 | 姿态来源 |
|---|---|---|---|---|
| `infantry` | **串口** `io::Gimbal` | 串口（同链路双向） | ❌ | 串口四元数 |
| `hero` | **串口** `io::Gimbal` | 串口 | ❌ | 串口四元数 |
| `sentry` | **CAN** `io::CBoard` | CAN | ⭐ **有** | CAN 四元数 |
| `uav` | **CAN** `io::CBoard` | CAN | ❌ | CAN 四元数 + **独立 DM_IMU 串口** |

**代码入口**：

| 兵种 | board 创建处 |
|---|---|
| `infantry` | `src/infantry.cpp` → `io::make_board(...)`（W54 自动感应） |
| `hero` | `src/hero.cpp` → `io::make_board(...)` |
| `sentry` | `src/sentry.cpp` → `io::CBoard`（模板参数，录像时用 `ReplayCBoard`） |
| `uav` | `src/uav.cpp` → `io::CBoard`（同上） |

⭐ **上游对照**（`vision_v2/upstream/sp_vision_25/src/`）：
`standard_mpc.cpp` 用 `io::Gimbal` · `sentry_multithread.cpp` 用 `io::CBoard` + `io::ROS2` · `uav.cpp` 用 `io::CBoard`
⇒ **一致**。

## 2. 串口链路（infantry / hero）—— `io::Gimbal`

### 2.1 配置

```yaml
# params/robots/infantry.yaml（hero 同）
com_port: "/dev/gimbal"
```

### 2.2 帧格式（`io/board/gimbal/gimbal.hpp`）

⭐ **两个固定长度、`__attribute__((packed))` 的结构体，均 `static_assert(sizeof(...) <= 64)`，带 CRC16。**

**下行 `VisionToGimbal`**：
```cpp
uint8_t  head[2] = {'S','P'};   // 帧头
uint8_t  mode;                  // 0=不控制 1=控制云台不开火 2=控制云台且开火
float    yaw, yaw_vel, yaw_acc; // ⭐ 含前馈（vel/acc）—— 同济 MPC 需要
float    pitch, pitch_vel, pitch_acc;
uint16_t crc16;
```

**上行 `GimbalToVision`**：
```cpp
uint8_t  head[2] = {'S','P'};
uint8_t  mode;                  // 0=空闲 1=自瞄 2=小符 3=大符
float    q[4];                  // ⭐ wxyz 顺序四元数（云台姿态）
float    yaw, yaw_vel, pitch, pitch_vel;
float    bullet_speed;
uint16_t bullet_count;          // 子弹累计发送次数
uint16_t crc16;
```

### 2.3 关键行为

- ⭐ **同一个串口双向**：`read_thread` 后台收上行，`send()` 写下行
- ⚠️ **掉线重连**：打不开串口时**每 100 ms 重试**（首条 + 每 50 次各报一次日志，W109 降噪）
- ⚠️ **没插硬件**：`make_board` 自动降级 `VirtualBoard` + 警告（见 §5）

## 3. CAN 链路（sentry / uav）—— `io::CBoard`

### 3.1 配置

```yaml
# params/robots/sentry.yaml
quaternion_canid: 0x01        # ⭐ 上行：四元数
bullet_speed_canid: 0x110     # ⭐ 上行：弹速 + 档位
send_canid: 0xff              # ⭐ 下行
can_interface: "can0"

# params/robots/uav.yaml
quaternion_canid: 0x001       # ⚠️ 与哨兵不同
bullet_speed_canid: 0x110
send_canid: 0xff
can_interface: "can0"
```

⚠️ **注意 CAN ID 各兵种不同**（`sentry` 用 `0x01`，`uav` 用 `0x001`）。
⚠️ `infantry.yaml` / `hero.yaml` 里**也有**这套 CAN 配置，但两者**实际走串口**，该段不生效。

### 3.2 帧格式（`io/board/can/cboard.cpp` 的 `callback`）

⭐ **上行帧按 CAN ID 区分**（`SocketCAN` 收到后在 `callback` 里分派）：

| CAN ID | 字段 | 编码 |
|---|---|---|
| `quaternion_canid` | `x, y, z, w` | `int16` 大端 ÷ 1e4；⚠️ **校验 `|q|²-1| < 1e-2`**，不合法则 warn 并丢弃 |
| `bullet_speed_canid` | `bullet_speed` | `int16` 大端 ÷ 1e2 |
| | `mode` | `uint8`（档位） |
| | `shoot_mode` | `uint8`（哨兵左/右/双枪口） |
| | `ft_angle` | `int16` 大端 ÷ 1e4（摩擦轮角度） |

⭐ **下行**（`send_canid`，`can_dlc = 8`，**单帧 8 字节**）：
```
data[0]          = control              (uint8, 0/1)
data[1]          = shoot                (uint8, 0/1)
data[2..3]       = yaw   × 1e4          (int16 大端)
data[4..5]       = pitch × 1e4          (int16 大端)
data[6..7]       = horizon_distance×1e4 (int16 大端；⚠️ 无人机专有字段)
```
⚠️ 注意：**yaw/pitch 之外还发 `horizon_distance`** —— 这是 `io::Command` 里**无人机专有**的字段。

### 3.3 ⚠️ 与 `io::Gimbal` 的接口差异（W31 记录）

| | `io::Gimbal` | `io::CBoard` |
|---|---|---|
| 下发 | `send(8 个标量)` | `send(io::Command)` |
| 姿态 | `q(t)`（四元数队列） | `imu_at(t)` |
| 档位 | `mode()`（`GimbalMode`） | 公开成员 `Mode mode` + `ShootMode shoot_mode` |

⭐ **不为了统一而改 `CBoard`** —— 而是把主循环写成**模板**，让两种下位机各实例化一次。

## 4. ROS2 链路（仅 sentry）—— 导航桥

⭐ **只有哨兵接 ROS2**（与同济一致）。启动日志：
```
[sentry] ROS2 导航桥已启动（上行 auto_aim_target_pos / 下行 enemy_status+autoaim_target）
```

### 4.1 下行（导航 → 视觉）—— `io/ros2/subscribe2nav.cpp`

| 话题消息 | 用途 | 接到哪 |
|---|---|---|
| `sp_msgs::msg::EnemyStatusMsg` | ⭐ **无敌状态**（哪些编号处于无敌） | `tracker.set_invincible(InvincibleMask)` |
| `sp_msgs::msg::AutoaimTargetMsg` | ⭐ **集火指令**（上级指定打谁） | `tracker.set_auto_aim_targets(...)` |

### 4.2 上行（视觉 → 导航）—— `io/ros2/publish2nav.cpp`

| 话题 | 消息类型 | 内容 |
|---|---|---|
| `auto_aim_target_pos` | `std_msgs::msg::String` | ⭐ **目标位置**（供导航决策） |

### 4.3 ⚠️ 依赖 `source` 工作空间

⚠️ **不 `source ros2_ws/install/setup.bash` 时，`sp_msgs` 的消息类型未注册**
⇒ `create_subscription` 抛 `rclcpp::exceptions::RCLError: type_support is null`。

⭐ **本项目 W108 已加 `try/catch`**：不再崩溃，而是报出可操作的错误并返回。

## 5. 无硬件时的自动降级 —— `io::make_board`（W54）

⭐ **infantry / hero 共用**（sentry / uav 直接建 `CBoard`，不降级）。

| `--no-board` | `com_port` 存在 | `--strict-board` | 结果 |
|---|---|---|---|
| 是 | — | — | ⭐ `VirtualBoard`（显式要求无板） |
| 否 | ✅ | — | `Gimbal`（真下位机） |
| 否 | ❌ | 否 | ⭐ **`VirtualBoard` + 大声警告**（默认降级） |
| 否 | ❌ | **是** | ❌ **报错退出**（= 同济行为） |

⭐ **默认降级的理由**：没接硬件是**开发机的常态**，直接崩体验差。
⚠️ **比赛用 `--strict-board`** —— "宁可失败也不要静默跑错"。

## 6. 无人机的额外串口 —— DM_IMU

⭐ **`uav` 除 CAN 外，还有一条独立的 IMU 串口**（`drivers/dm_imu/`）：

```cpp
serial_.setBaudrate(921600);   // ⚠️ 全项目唯一显式设波特率的地方
```

⭐ **用途**：无人机需要更高频率/更低延迟的姿态，不复用 CAN 上的四元数。

---

## 7. 录像模式：不通信

⭐ **录像模式用 `ReplayBoard`（infantry/hero）或 `ReplayCBoard`（sentry/uav）**：

| | 是什么 |
|---|---|
| `io::ReplayBoard` | 复用 `io::ReplayBoard`（`io/board/replay.hpp`），从 `demo.txt` 回放四元数，`send()` 只记录不发送 |
| `ReplayCBoard` | ⭐ **定义在各自主循环里**，**刻意模仿 `io::CBoard` 的公开形状**（`mode` / `bullet_speed` / `shoot_mode` / `imu_at` / `send(Command)`）⇒ 主循环模板**一份逻辑两种下位机** |

⚠️ **录像模式下的固有限制**：云台是"死的"（只回放录制的四元数，不真转）
⇒ ⭐ 这会导致"用当前云台姿态投影未来瞄准点"失效（见 [docs/20](20-运行效率对比-改造架构vs同济.md) 与 W117）。

---

## 8. 一句话总结

| 兵种 | 一句话 |
|---|---|
| `infantry` / `hero` | ⭐ **串口**（`/dev/gimbal`），`'S','P'` 帧头 + CRC16 的定长结构，**双向同链路** |
| `sentry` | ⭐ **CAN**（`can0`，ID `0x01`/`0x110`/`0xff`）+ ⭐ **ROS2 导航桥**（无敌状态↓ / 集火指令↓ / 目标位置↑） |
| `uav` | ⭐ **CAN**（ID `0x001`/`0x110`/`0xff`）+ **独立 DM_IMU 串口 @921600** |
| 四者共同 | 录像模式下一律替换为**回放替身**，不进行真实通信 |
