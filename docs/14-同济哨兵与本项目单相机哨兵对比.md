> ⭐ 核心差异：**同济哨兵是「4 相机全向感知」；本项目哨兵与步兵一样只有 1 个相机。**
>

## 14.2 同济哨兵的完整数据流（以 `sentry.cpp` 为准）

```cpp
// ── 硬件：4 个相机 ──
io::Camera    camera(config_path);                  // 前（hikrobot，主相机）
io::Camera    back_camera("configs/camera.yaml");   // 后 ⚠️ 另一份 yaml
io::USBCamera usbcam1("video0", config_path);       // 左 USB
io::USBCamera usbcam2("video2", config_path);       // 右 USB
io::CBoard    cboard(config_path);                  // CAN 下位机
io::ROS2      ros2;                                 // ⭐ 与导航/电控通信

// ── 自瞄链路（与步兵相同）──
yolo / solver / tracker / aimer / shooter
omniperception::Decider decider(config_path);       // ⭐ 哨兵专属

while (!exiter.exit()) {
  camera.read(img, timestamp);
  q = cboard.imu_at(timestamp - 1ms);
  solver.set_R_gimbal2world(q);
  gimbal_pos = tools::eulers(solver.R_gimbal2world(), 2, 1, 0);

  armors = yolo.detect(img);

  // ═══ ⭐ 哨兵专属的 4 项横切能力（顺序固定！）═══
  decider.get_invincible_armor(ros2.subscribe_enemy_status());   // ① 无敌状态
  decider.armor_filter(armors);                                  // ② 5 条射击过滤
  // decider.get_auto_aim_target(armors, ros2.subscribe_autoaim_target());  // ③ 集火（注释）
  decider.set_priority(armors);                                  // ④ 优先级

  targets = tracker.track(armors, timestamp);

  io::Command command{false, false, 0, 0};
  // ═══ ⭐⭐ 全向搜索 vs 自瞄（由 tracker 状态决定）═══
  if (tracker.state() == "lost")
    command = decider.decide(yolo, gimbal_pos, usbcam1, usbcam2, back_camera);  // 轮询 3 相机
  else
    command = aimer.aim(targets, timestamp, cboard.bullet_speed, cboard.shoot_mode);

  command.shoot = shooter.shoot(command, aimer, targets, gimbal_pos);
  cboard.send(command);

  ros2.publish(decider.get_target_info(armors, targets));   // ⭐ 上行给导航
}
```

⭐⭐ **关键结构**：**「4 项横切能力」是独立于相机数的一层**，
夹在 `yolo.detect()` 与 `tracker.track()` **之间** —— 这正是本项目 W7 把它们捞出来的依据。

## 14.5 ⭐⭐⭐ `decide()` 全向搜索的实现细节（供理解，本项目不用）

```cpp
io::Command Decider::decide(yolo, gimbal_pos, usbcam1, usbcam2, back_camera)
{
  io::USBCamera* cams[] = {&usbcam1, &usbcam2};
  if (count_ == 2) back_camera.read(usb_img, timestamp);
  else             cams[count_]->read(usb_img, timestamp);      // ⭐ 每帧只读 1 个相机

  auto armors = yolo.detect(usb_img);
  auto empty  = armor_filter(armors);

  if (!empty) {
    delta_angle = (count_ == 2) ? delta_angle(armors, "back")
                                : delta_angle(armors, cams[count_]->device_name);
    count_ = (count_ + 1) % 3;                                  // ⭐ 轮询
    return io::Command{true, false,                             // ⭐ control=true, fire=FALSE
                       limit_rad(gimbal_pos[0] + delta_angle[0] / 57.3),
                       limit_rad(delta_angle[1] / 57.3)};
  }
  count_ = (count_ + 1) % 3;
  return io::Command{false, false, 0, 0};
}
```

**三个要点**：
1. ⭐ **轮询**：`count_ = (count_+1) % 3`，每帧只读一个相机 → **省算力**（4 相机不可能帧帧全跑 YOLO）
2. ⭐ **只转不射**：`fire = false` —— 全向搜索只负责"把云台转向目标"，找到后交给 `tracker`/`aimer` 接管
3. ⚠️ **`delta_angle()` 全是硬编码的机械安装角**：
   ```cpp
   if (camera == "left")  delta_angle[0] =  62 + new_fov_h_/2 - center_norm.x * new_fov_h_;
   if (camera == "right") delta_angle[0] = -62 + new_fov_h_/2 - ...;
   else /* back */        delta_angle[0] = 170 + 54.2/2 - center_norm.x * 54.2;   // ⚠️ FOV 也没走 yaml
   ```
   → **换一台哨兵就失效**（左/右 62°、后 170°、后 FOV 54.2 都是那一台车的实物角度）

## 14.6 本项目单相机哨兵的设计

### ⭐ 本项目比同济多出来的 4 项横切能力（**默认关闭 = 同济行为**）

## 14.7 ⚠️ 两个**待与电控核对**的点（本项目已按更保守的方式处理）

### ① 无敌 ID 映射：注释自相矛盾

```cpp
// decider.hpp:60
std::vector<auto_aim::ArmorName> invincible_armor_;  // 无敌状态机器人编号,英雄为1，哨兵为6
```
⚠️ **RM 标准的机器人 ID 是「6 = 空中 / 7 = 哨兵」**，注释写「哨兵为6」与之矛盾。

**同济的做法**（**无边界检查**）：
```cpp
invincible_armor_.push_back(auto_aim::ArmorName(id - 1));   // ⚠️ 隐式减法，枚举一改全错
```
**对比**：同一个文件里的 `get_auto_aim_target` **有**边界检查：
```cpp
if (target <= 0 || static_cast<size_t>(target) > ARMOR_NAMES.size()) { warn; continue; }
```

**本项目的做法**（W7）：`InvincibleMask` 位掩码 + **显式映射表** `ENEMY_ID_TO_ARMOR`
（未知 id 返回 `not_armor`，**不越界**），并标注「⚠️ 待与电控核对」。

### ② `get_target_info` 的 `name + 1`

```cpp
return Eigen::Vector4d{armor.xyz_in_gimbal[0], armor.xyz_in_gimbal[1], 1,
                       static_cast<double>(armor.name) + 1};   // 避免歧义+1(详见通信协议)
```
⭐ 上行 id 从 **1** 开始（`ArmorName` 从 0 开始）—— 接线时必须遵守。

## 14.9 ✅ 本项目实现（W33）

### `src/sentry.cpp` —— **一个循环，两个实例**

```
camera : io::CameraBase*   ← io::Camera（真实） / io::VideoCamera（录像）   [W10 已统一]
board  : 模板参数          ← io::CBoard（真实 CAN） / ReplayCBoard（录像替身）
```

⚠️ **为什么不给 `CBoard` 加适配器**：W31 已判定 `CBoard` 的 API 与 `Gimbal` 本质不同，
强行统一要改同济代码。这里改为 **`run_sentry<Board>()` 模板** ——
`ReplayCBoard` 刻意模仿 `CBoard` 的公开形状（`bullet_speed`/`mode`/`shoot_mode`/`imu_at`/`send`），
**一份主循环逻辑，两种下位机各实例化一次**。

### ⭐⭐ 从同济 `sentry.cpp` **显式去掉**的东西

| 去掉的 | 代码位置（同济） | 理由 |
|---|---|---|
| 3 个额外相机 | `back_camera` + `usbcam1` + `usbcam2` | 本项目哨兵单相机 |
| 全向搜索 | `decider.decide(yolo, gimbal_pos, usbcam1, usbcam2, back_camera)` | 没有侧后相机 |
| 硬编码安装角 | `delta_angle()` 的 `62 / −62 / 170 / 54.2` | 同上 |
| 多相机队列 | `Perceptron` + `decider.sort()` + `decide(detection_queue)` | 同上 |

代码里对这些位置都有 **`⚠️` 注释说明"同济此处有全向搜索，本项目单相机去掉"** —— 便于对照。

### ⭐ 计时口径的一个坑（实测踩到）

第一版把 `expense.begin("perceive")` 放在 `detect` **之前**、`end` 放在**最后**，
于是 `perceive` **包住**了 `detect` → `scripts/analyze.py` 的 `budget_table`
（**假设各段正交**）把它们相加 → 合计 **158.79%**（虚高）。

**修法**：与 infantry 一致，`expense.end("perceive")` 放在 **detect 分支之前** → 各段正交。

**修正后实测**（单相机哨兵，CPU 推理，剔除 3 帧热身）：

```
── 帧预算占用（10 ms 周期 @100 Hz）──
  det_t_infer_us    6744.6us   67.45%    ← YOLO 推理
  t_perceive_us     2064.3us   20.64%    ← 取图 + 姿态 + 记录 + 坐标变换
  trk_t_track_us       3.7us    0.04%
  合计              8812.7us   88.13%
```

⭐ 与步兵（82.74%）**同量级**，合理 —— 哨兵的额外开销在 `MODES`/`ShootMode` 分支，
检测与跟踪与步兵**完全一致**（因为哨兵的自瞄链路与步兵相同）。
